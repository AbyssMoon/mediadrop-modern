КРАТКО
======

MediaDrop Modern — рабочий Python 3 / FastAPI runtime для существующей MediaDrop.
Он сохраняет совместимость с полезной legacy SQL-схемой и старым файловым архивом,
но не тащит обратно Python 2/Pylons/Flash/transcoding framework.

Текущий automated suite: 43 passed.

Основные документы:
- docs/DEPLOYMENT_RU.md — production deployment, реальные host/container mounts,
  permissions, внешний nginx, fresh install и legacy migration;
- docs/OPERATIONS_RU.md — backup/restore, upgrade, smoke checks, troubleshooting;
- MIGRATION_NOTES.md — детали перехода со старого MediaDrop и production handoff;
- README.md — обзор проекта и быстрый старт.

Главное правило эксплуатации:
- legacy MariaDB и старый media/images archive — compatibility boundary;
- старые media/images монтируются только read-only;
- новые uploads/previews/SQLite/logs хранятся отдельно;
- project name Compose должен оставаться стабильным;
- обычный upgrade никогда не делается через `docker compose down -v`.

===============================================================================
1. PRODUCTION STORAGE
===============================================================================

Default host roots:

  MODERN_DATA_ROOT=/opt/mediadrop-modern-data
  LEGACY_DATA_ROOT=/opt/mediadrop_data
  COMPOSE_PROJECT_NAME=mediadrop-modern

Реальные mounts:

  HOST                                             CONTAINER             MODE
  /opt/mediadrop-modern-data/media                /data/media           rw
  /opt/mediadrop-modern-data/images               /data/images          rw
  /opt/mediadrop-modern-data/modern               /data/modern          rw
  /opt/mediadrop-modern-data/logs                 /data/logs            rw
  /opt/mediadrop_data/media                       /data/legacy-media    ro
  /opt/mediadrop_data/images                      /data/legacy-images   ro

MariaDB:
  Docker named volume mediadrop-modern_mediadrop_db
  -> /var/lib/mysql внутри db container.

Почему фиксируем COMPOSE_PROJECT_NAME:
Docker Compose добавляет project name к named volume. Если при обновлении распаковать
релиз в другой каталог и получить другой project name, можно случайно стартовать с
новым пустым DB volume. Поэтому `.env` держит:

  COMPOSE_PROJECT_NAME=mediadrop-modern

Подробности и команды проверки: docs/DEPLOYMENT_RU.md.

===============================================================================
2. DATA MODEL
===============================================================================

Legacy-compatible MariaDB содержит основной контент:
- media / media_files / storage;
- categories/tags;
- comments;
- podcasts;
- settings;
- local users/groups/permissions;
- другие старые таблицы, пока сохраняется rollback compatibility.

Modern-only SQLite:
  /data/modern/mediadrop-modern.db

При default mount физически:
  /opt/mediadrop-modern-data/modern/mediadrop-modern.db

В sidecar находятся modern auth/LDAP/account settings. Основной media content туда
не переносится.

===============================================================================
3. PUBLIC / PLAYER
===============================================================================

Работают библиотека, поиск, categories, tags, podcasts, media pages, comments,
like/dislike, downloads по настройке, feeds/sitemap и JSON API.

Player — native HTML5 video/audio плюс небольшая панель:
- -10 / +10 секунд;
- speed 0.5x..2x;
- mute/unmute;
- fullscreen;
- Picture-in-Picture;
- wide mode;
- help по shortcuts.

Shortcuts:
- Space/K — play/pause;
- Left/Right — seek;
- M — mute;
- F — fullscreen;
- P — PiP.

Если downloads выключены в настройках, video получает `controlslist="nodownload"`.
Поддерживающие браузеры скрывают native Download action. Это не DRM.

С 0.6.4 `/files/*` освобождает DB connection до фактической отправки video response.
Частая перемотка/Range requests больше не должны выбивать SQLAlchemy QueuePool.

===============================================================================
4. COMMENTS
===============================================================================

Для авторизованного пользователя Name/Email в форме комментария берутся из текущей
identity и read-only в UI. Backend также принудительно использует authenticated
principal, поэтому подмена полей в POST не меняет автора.

Для анонимного пользователя поля остаются editable, когда анонимный доступ разрешён.

===============================================================================
5. AUTH / LDAP
===============================================================================

Поддерживаются:
- mandatory sign-in или public mode;
- session TTL 8h / 1d / 1w / 30d;
- LDAP/LDAPS;
- bind account + encrypted password;
- configurable Base DN/search base/filter/attributes;
- optional CA для internal LDAPS;
- Access / Editor / Admin mappings;
- fallback на local MediaDrop account.

Local passwords — Argon2id. Старый SHA-1 обновляется lazy после успешного login, пока
старый hash сохраняется для rollback window.

SECRET_KEY нужно сохранять между обновлениями/restore: от него зависят sessions и
расшифровка LDAP bind password.

===============================================================================
6. FRESH INSTALL VS LEGACY IMPORT
===============================================================================

Fresh empty install:

  cp .env.example .env
  # настроить passwords, SECRET_KEY и host paths
  docker compose build
  docker compose up -d db
  docker compose run --rm app mediadrop init-db
  docker compose run --rm app mediadrop create-admin admin admin@example.com
  docker compose up -d

Legacy import:
- восстановить старый SQL dump;
- положить старые media/images под LEGACY_DATA_ROOT;
- mounts только `:ro`;
- НЕ запускать `mediadrop init-db`;
- выполнить:

  docker compose run --rm app python scripts/check_legacy_db.py
  docker compose run --rm app python scripts/check_legacy_thumbnails.py
  docker compose run --rm app python scripts/list_unplayable_media.py

===============================================================================
7. EXTERNAL NGINX
===============================================================================

Если nginx находится на отдельном корпоративном хосте и делает обычный proxy_pass,
оставлять:

  MEDIA_SERVE_MODE=app

и выставить BIND_ADDR в private IP Docker-хоста, который доступен nginx. `127.0.0.1`
подходит только если reverse proxy находится на том же хосте. `0.0.0.0` допустим при
жёстком firewall, но лучше bind на конкретный private IP.

`MEDIA_SERVE_MODE=nginx` / X-Accel-Redirect имеет смысл только когда nginx физически
видит тот же media filesystem. Удалённый reverse proxy не может сам открыть
`/data/media` контейнера приложения.

===============================================================================
8. BACKUP / UPGRADE
===============================================================================

scripts/backup.sh сохраняет:
- MariaDB logical dump;
- modern SQLite consistent backup;
- новые media/images;
- .env + compose.yml;
- SHA256SUMS.

Legacy read-only archive намеренно не дублируется в этот backup и должен иметь
отдельный retention.

Перед upgrade:

  ./scripts/backup.sh
  docker compose config --volumes
  grep -E '^(COMPOSE_PROJECT_NAME|MODERN_DATA_ROOT|LEGACY_DATA_ROOT)=' .env

После замены кода:

  docker compose build --no-cache app
  docker compose up -d
  docker compose ps
  curl -fsS http://127.0.0.1:8080/healthz

НИКОГДА не использовать `docker compose down -v` как обычную команду обновления.
