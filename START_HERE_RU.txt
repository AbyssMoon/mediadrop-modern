Версия: 0.5.4

КРАТКОЕ СОСТОЯНИЕ
=================

MediaDrop Modern уже является рабочим современным runtime для существующей MediaDrop.
Он работает на реальном импортированном legacy dump и старом каталоге файлов, основной
public/admin функционал проверен вручную, automated suite: 32 passed.

Это больше не стадия "попробовать переписать MediaDrop". Текущая задача проекта —
эксплуатация и точечное улучшение рабочего runtime при сохранении простой возможности
перенести/вернуть legacy-данные.

Главное правило проекта:
- web/runtime новый;
- legacy database и старый файловый архив остаются compatibility boundary;
- старые media/images при миграции держим read-only;
- новые данные пишем отдельно;
- не возвращаем Pylons/Flash/transcoding framework только ради совместимости.

Не блокируют текущий релиз, но остаются дальнейшими задачами:
- offline FLV -> MP4 для старых FLV-only материалов;
- позже перейти с legacy SHA1 password hashes на Argon2id;
- постепенно довести остальные локали до уровня RU/EN;
- после закрытия rollback window можно чистить ненужную legacy schema;
- при большой нагрузке можно вынести media delivery в nginx X-Accel-Redirect.

================================================================================
1. ЧТО ЭТО ЗА ПРОЕКТ
================================================================================

Исходный продукт: MediaDrop (github.com/mediadrop/mediadrop).

Старый MediaDrop работал на Python 2.6/2.7, Pylons/Paste/Routes/Genshi, старом
SQLAlchemy, repoze.who, ToscaWidgets и отдельной системе players/storage/transcoding.

Вместо прямого порта этого framework-слоя сделан небольшой новый runtime:
- Python 3.13 (проект поддерживает >=3.12);
- FastAPI / Starlette;
- SQLAlchemy 2.x;
- Jinja2;
- обычные CSS/JS без Node/npm build;
- Uvicorn;
- MariaDB 11.4;
- Pillow;
- native HTML5 video/audio;
- ldap3 + cryptography;
- pytest.

Удалено намеренно:
- Pylons/Paste/Routes/ToscaWidgets/Genshi runtime;
- старый plugin runtime;
- encoding/transcoding workers, очереди, профили и presets;
- Flash/RTMP;
- старый player-selection framework;
- encoder/player-era admin settings.

`encoded=true` теперь означает, что к материалу прикреплён уже готовый для браузера
файл. Автоматического transcoding после upload нет.

================================================================================
2. COMPATIBILITY BOUNDARY
================================================================================

Совместимость держится на:
- существующей MediaDrop SQL-схеме для контента и local users;
- media_files.unique_id и старом local-file layout;
- основных public URL;
- reviewed / encoded / publishable / publish_on semantics;
- categories/tags/podcasts/comments/settings;
- users/groups/permissions на переходный период;
- старом layout thumbnails.

Именно поэтому старую установку можно переносить без большой обязательной migration.

3. ХРАНЕНИЕ ДАННЫХ
================================================================================

Основная legacy-compatible MariaDB:
- media;
- media_files, storage;
- categories/media_categories;
- tags/media_tags;
- comments;
- podcasts;
- users/groups/permissions/users_groups/groups_permissions;
- settings;
- и прочие старые таблицы, которые пока не удаляются.

Modern-only настройки авторизации хранятся ОТДЕЛЬНО:
  MODERN_DATABASE_URL=sqlite:////data/modern/mediadrop-modern.db

Default Docker layout:
  /data/legacy-media   — старые media, read-only
  /data/legacy-images  — старые images, read-only
  /data/media          — новые uploads, writable
  /data/images         — новые previews, writable
  /data/modern         — modern sidecar DB, writable

Если modern sidecar отсутствует, он создаётся заново. Default безопасный для legacy
migration: сайт публичный, LDAP выключен.

5. PLAYER
================================================================================

Основа — native `<video controls>`, не отдельный тяжёлый player framework.

Дополнительная панель:
- -10 / +10 sec;
- speed 0.5x / 0.75x / 1x / 1.25x / 1.5x / 1.75x / 2x;
- Picture-in-Picture;
- wide mode на странице материала;
- (i) с быстрыми клавишами.

Shortcuts:
- Space/K — play/pause;
- Left/Right — +/-10 sec;
- M — mute;
- F — fullscreen самого native video;
- P — PiP.

Wide mode расширяет media page и переносит "О материале" / категории / теги под
видео. Никакие player preferences не сохраняются в DB/localStorage/sessionStorage.

================================================================================
6. PREVIEWS
================================================================================

Legacy thumbnails читаются как есть:
  images/media/<media_id>s.jpg
  images/media/<media_id>m.jpg
  images/media/<media_id>l.jpg
  images/media/<media_id>orig.<ext>

Новые preview uploads создают те же совместимые имена, но размеры больше:
- s: до 320x180;
- m: до 960x540;
- l: до 1920x1080.

Маленькие исходники не растягиваются вверх. Принимаются JPEG/PNG/WebP.

7. ЯЗЫКИ
================================================================================

Fresh install default: English (`LOCALE=en`).

Глобальный язык сайта меняется через Admin -> Settings и хранится в legacy `settings`.
Публичный переключатель языка хранит выбор только в cookie конкретного браузера.

RU и EN покрывают текущий modern UI. Остальные исторические MediaDrop locale доступны,
но недостающие строки fallback-ятся на English. Arabic/Hebrew поддерживают RTL.

================================================================================
8. AUTH / LDAP
================================================================================

Admin -> Authentication:
- public access или обязательный login;
- session cookie lifetime: 8 часов / сутки / неделя / 30 дней;
- LDAP enable/disable;
- ldap:// и ldaps://;
- Bind DN / bind password;
- Base DN / User search base / User filter;
- username/display name/email/memberOf attributes;
- CA path для внутреннего LDAPS;
- Access / Editor / Admin group mappings.

ROLE MODEL:
- Access — войти и смотреть сайт при mandatory login;
- Editor — Access + Media/Comments administration и upload/edit;
- Admin — Editor + Settings/Auth/Users/Categories/Podcasts.

Editor/Admin автоматически дают Access.
Используется прямой memberOf; nested groups специально не раскрываются.

AUTH ORDER:
1) LDAP, если включён;
2) local legacy account как fallback.

Если login одинаковый в LDAP и local, сначала проверяется LDAP. Local break-glass
accounts при этом остаются рабочими. LDAP users НЕ создаются в legacy `users`.

Старая local group `admins` считается full admin даже в legacy DB, где у неё исторически
есть только permission `edit`. Fresh `mediadrop create-admin` создаёт edit + admin.

LDAP bind password шифруется ключом, производным от `SECRET_KEY`.
Если перенести sidecar, нужно сохранить тот же `SECRET_KEY`. При смене SECRET_KEY
контент не ломается, но старые sessions инвалидируются и bind password вводится заново.

10. FLV — КАК ЧИНИТЬ, НЕ ЛОМАЯ LEGACY
================================================================================

FLV не поддерживается современными браузерами. Flash/FLV player возвращать не нужно.

Сначала получить read-only inventory:

  docker compose run --rm app python scripts/list_unplayable_media.py

Скрипт показывает media id/title/slug, file_id, format, unique_id, путь и наличие
исходного файла. Ничего не меняет.

Рекомендуемый workflow для каждого FLV:

1. Старый FLV НЕ менять и НЕ удалять.
2. Перекодировать отдельную копию в MP4/H.264/AAC:

  ffmpeg \
    -i /path/to/source.flv \
    -map 0:v:0 -map 0:a:0? \
    -c:v libx264 \
    -preset medium \
    -crf 20 \
    -pix_fmt yuv420p \
    -c:a aac \
    -b:a 160k \
    -movflags +faststart \
    /tmp/converted.mp4

3. Проверить streams/duration:

  ffprobe -v error \
    -show_entries format=duration:stream=codec_type,codec_name,width,height \
    -of json \
    /tmp/converted.mp4

4. Прочитать весь output для проверки ошибок:

  ffmpeg -v error -i /tmp/converted.mp4 -f null -

5. Открыть тот же media item в Admin и прикрепить новый MP4.

Новый файл попадёт в `/data/media` с новым generated unique_id и новой строкой
`media_files`. Старый FLV останется в `/data/legacy-media` read-only и старая строка
тоже сохранится.

Это предпочтительный вариант до конца rollback window: modern player использует
browser-ready MP4, но legacy source не уничтожен.

Не удалять старые FLV, пока rollback к старой MediaDrop ещё нужен.

================================================================================
11. FRESH INSTALL
================================================================================

1. Подготовить `.env`:

  cp .env.example .env

Обязательно заменить:
  DB_PASSWORD
  DB_ROOT_PASSWORD
  SECRET_KEY

Для local HTTP test:
  COOKIE_SECURE=false

Для production HTTPS:
  COOKIE_SECURE=true

2. Даже для fresh install удобно иметь пустой legacy root, чтобы bind mounts не
создавали неожиданные каталоги:

  mkdir -p /opt/mediadrop_data/media /opt/mediadrop_data/images

3. Build/start:

  docker compose build
  docker compose up -d db
  docker compose run --rm app mediadrop init-db
  docker compose run --rm app mediadrop create-admin admin admin@example.com
  docker compose up -d

4. Проверка:

  docker compose ps
  docker compose logs --tail=100 app
  curl -fsS http://127.0.0.1:8080/healthz

ВАЖНО: `init-db` только для новой пустой установки.

================================================================================
12. LEGACY IMPORT
================================================================================

Ожидаемый host layout, например:

  /opt/mediadrop_data/
    media/
    images/
    mediadrop.sql.gz

В `.env`:

  LEGACY_DATA_ROOT=/opt/mediadrop_data

Compose монтирует old archive read-only:
  media  -> /data/legacy-media:ro
  images -> /data/legacy-images:ro

Новые данные идут отдельно:
  mediadrop_media  -> /data/media
  mediadrop_images -> /data/images
  mediadrop_modern -> /data/modern

Migration steps:

1. Проверить dump:

  gzip -t /opt/mediadrop_data/mediadrop.sql.gz

2. Build/start DB:

  docker compose build
  docker compose up -d db

3. Импортировать legacy SQL dump в MariaDB.

4. НЕ запускать `mediadrop init-db` после импорта.

5. Read-only checks:

  docker compose run --rm app python scripts/check_legacy_db.py
  docker compose run --rm app python scripts/check_legacy_thumbnails.py
  docker compose run --rm app python scripts/list_unplayable_media.py

6. Запустить app:

  docker compose up -d --force-recreate app
  docker compose logs --tail=100 app

7. Проверить representative content:
- главную;
- несколько MP4 media pages;
- categories/tags;
- admin login;
- settings;
- comments;
- previews;
- новый MP4 upload + preview;
- LDAP live bind, если LDAP будет использоваться.

================================================================================
14. SECURITY / PRODUCTION
================================================================================

- `.env` и реальные credentials не хранить в git.
- `SECRET_KEY` и DB passwords должны быть длинными случайными значениями.
- Legacy media/images держать read-only до закрытия migration/rollback window.
- Production запускать за nginx/Caddy + HTTPS.
- `COOKIE_SECURE=true` для HTTPS; при прямом HTTP test нужен false.
- Uvicorn:8080 без необходимости наружу не публиковать.
- Legacy SHA1 passwords сохранены только ради бесшовного перехода.
- Sidecar backup для LDAP имеет смысл хранить вместе с тем же `SECRET_KEY`.
- Live LDAP bind нужно проверить в реальной сети перед включением mandatory auth.

================================================================================
15. ЧТО НЕ НАДО СЛУЧАЙНО ОТКАТЫВАТЬ
================================================================================

1. Не портировать Pylons один-в-один.
2. Не возвращать постоянный transcoding pipeline.
3. Не менять legacy schema без необходимости, пока важен rollback.
4. Не писать новые uploads в legacy media/images archive.
5. Не удалять старые FLV после конвертации до окончания rollback window.
6. Не синхронизировать LDAP users в legacy `users` без отдельной причины.
7. Не превращать UI в SPA без необходимости — Jinja + CSS/JS достаточно.
8. Не делать destructive cleanup encoder/player/fulltext tables без inventory/backup.
